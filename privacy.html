Privacy Policy & On-Device Security Specification

Technical Privacy Protocol & Legal Compliance Specification • Version 1.0.0
Architect & Principal Author: Ansari Bilal (ansaribilal.com)
Effective Date: August 21, 2026
Abstract & Zero-Exfiltration Guarantee

This document establishes the formal data protection, execution threat model, and privacy architecture of the Momo TTS mobile application. Momo TTS enforces a deterministic Zero-Exfiltration Architecture: all neural acoustic synthesis, phonemization, text chunking, and master audio stitching execute strictly within the sandboxed local process memory of the host Android operating system. No user text, speech output, voice selection, or telemetry data is collected, stored, or transmitted over any external computer network.

1. Threat Model & Data Flow Architecture

To eliminate data surveillance vulnerabilities inherent in cloud-hosted Text-to-Speech APIs, Momo TTS operates under an isolated client-side execution model. The data pipeline adheres to the following computational boundaries:

  • Text Ingestion Layer: Text strings provided to the Voice Studio or Multi-Voice Dialogue Editor reside purely in ephemeral memory allocated to the application process. No remote logging or keystroke analysis is performed.
  • Inference Execution Layer: Neural graph execution runs exclusively on local hardware via compiled native ONNX runtimes. The model weights are read directly from sandboxed device storage without remote socket connections.
  • Audio Stitching Layer: Generated raw PCM samples are compiled into destination audio containers (WAV / MP3) on device. Files remain exclusively accessible to the host user until explicit manual export.

2. Storage Classification & Permissions

Momo TTS limits internal storage usage strictly to operational application requirements:

Storage Category Physical Location Persistence Lifetime User Control Mechanism
Voice Model Assets App-Private Internal Data (/data/user/0/.../models/) Retained until user uninstalls or deletes voice Voice Hub Management UI
Temporary Audio Chunks App-Private Cache (/tts_cache/) Temporary (Per-Session) 1-Tap Cache Purge in Settings
Project Metadata Sandboxed SQLite Database (projects.db) Persistent on device User Project Drawer Deletion

3. Telemetry, Analytics & Advertising

The application contains zero third-party behavioral analytics SDKs, zero advertising trackers, and zero crash-reporting trackers. Network interfaces are utilized strictly for user-initiated binary asset retrieval (downloading selected neural model weights from authenticated public repositories). Once model weights are locally cached, network interfaces remain completely idle during all synthesis operations.

4. Children's Online Privacy Protection (COPPA / GDPR)

Because Momo TTS collects zero personally identifiable information (PII) from any user, it operates in strict compliance with the Children's Online Privacy Protection Act (COPPA) and Article 8 of the General Data Protection Regulation (GDPR). The application is safe for users of all age brackets.

5. User Rights & Data Erasure

Under GDPR, CCPA, and global privacy frameworks, users retain complete, absolute ownership of their data. Because all assets exist locally:

  • Right to Access: All generated WAV and MP3 files are directly inspectable, playable, and exportable on the device.
  • Right to Erasure: Users can purge all temporary audio buffers instantly via Settings › Clear Temporary Audio Cache, or eliminate all project records by clearing application storage in Android System Settings.
